# 后训练与对齐

> [!abstract] 核心结论
> 后训练不是单一算法，而是把预训练模型调整为目标助手的数据—训练—评测闭环。SFT 用目标回答教模型“应该怎样答”，偏好优化用回答间的相对优劣调整行为；二者都不能替代独立评测，也不自动保证事实正确和安全。

## 总体流程

```text
预训练模型
→ SFT：学习指令、对话格式和目标回答
→ 偏好对齐
   ├─ Reward Model → 在线/离线 RL 优化
   └─ DPO 等直接偏好优化
→ 固定 Eval + Bad Case 分析
→ 构造针对性数据
→ 再训练与回归评测
```

基础语言和世界知识能力主要来自预训练；后训练更侧重激活、组织和约束已有能力，改变指令遵循、表达风格、安全边界和偏好表现。

## SFT

SFT（Supervised Fine-Tuning）使用高质量的“输入 → 目标回答”数据：

```text
system / user / context
→ assistant response
```

本质仍是 next-token cross entropy，但通常只对 assistant 区域计算 loss：

$$
L_{SFT}=-\frac{1}{N_{assistant}}\sum_t m_t\log\pi_\theta(y_t\mid x,y_{<t})
$$

$m_t$ 表示该 token 是否参与监督。若把 system/user token 也纳入 loss，模型会学习复述完整模板；若 mask、模板或 EOS 处理错误，训练 loss 仍可能下降，但生成行为会偏离目标。

SFT 主要学习：指令和聊天协议、任务格式、风格，以及给定输入时的期望输出。它是监督学习，不等同于强化学习，也不保证未知分布上的真实性。

## 偏好数据与 Reward Model

典型偏好样本为：

```text
prompt x
chosen y_w      更符合标注标准
rejected y_l    相对较差
```

`chosen` 只表示在当前标准和候选集合中相对更优，不代表绝对正确。来源可以是人工、规则、模型评审或混合流程，质量取决于评价标准、候选多样性和标注一致性。

Reward Model（RM）学习标量评分 $r_\phi(x,y)$。常见 pairwise Bradley–Terry loss 为：

$$
L_{RM}=-\log\sigma\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right)
$$

RM 负责评分，不负责最终生成。它只是目标偏好的代理，可能受到长度、风格、模板和训练分布偏差影响。

## RLHF 与 DPO

经典 RLHF 链路先训练 RM，再从当前策略采样回答，用奖励和相对参考策略的约束更新生成模型。KL 约束用于限制策略偏离过大，但具体算法、奖励塑形和采样方式会改变训练性质。

DPO 直接使用偏好对和参考模型。其常见目标为：

$$
L_{DPO}=-\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)}-
\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}
\right]\right)
$$

它提高 chosen 相对 rejected 的优势，并通过参考模型隐式约束策略。DPO 不显式训练 RM，也不运行完整在线 RL 采样环路；这不代表它没有目标函数、参考约束或分布外风险。

| 方法 | 主要数据 | 优化对象 | 主要边界 |
| --- | --- | --- | --- |
| SFT | 输入与目标回答 | token 条件似然 | 只能模仿给定答案 |
| Reward Model | 回答偏好对 | 相对评分 | 评分不是生成，可能被利用 |
| RLHF | 生成样本与奖励 | 期望奖励下的策略 | 系统复杂，需控制策略漂移 |
| DPO | chosen/rejected 与参考模型 | 相对偏好优势 | 离线数据覆盖决定学习边界 |

## Loss 与 Reward

- Loss 是优化器直接最小化的可微目标，如 SFT token 交叉熵。
- Reward 是希望最大化的行为评价，可能只在完整回答后得到，也可能不可微。
- 写成 `loss = -reward` 只是符号转换，不会让监督学习与强化学习的数据生成、信用分配和分布变化变得相同。
- Reward hacking 指模型提高代理奖励却偏离真实目标，因此必须结合独立 [[大模型评测]] 和 Bad Case。

## 数据闭环

```text
明确目标与不可接受行为
→ 建立冻结的 baseline eval
→ 聚类稳定复现的失败模式
→ 选择 SFT / preference / system 修复
→ 训练并记录数据、代码和 checkpoint
→ 比较目标指标与能力/安全回归
→ 只有通过门槛才发布
```

训练方法应由失败模式决定。格式错误可能适合 SFT；相对风格偏好可能适合偏好数据；知识缺失可能需要预训练、检索或工具，而不是盲目增加对齐数据。

## 易错点

> [!warning] 更符合偏好不等于更正确
> 偏好数据可能奖励长度、迎合或特定措辞，RM/DPO 还会放大标注和候选分布中的偏差。必须分别评测帮助性、真实性、安全性、能力保持和成本，不能只看训练 loss 或平均偏好胜率。
