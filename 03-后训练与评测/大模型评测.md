# 大模型评测

> [!abstract] 核心结论
> 评测要把“模型是否学会、是否泛化、是否安全、是否值得发布”转换为可复现证据。可靠 Eval 必须固定模型和数据版本，组合自动指标、人工判断与样本级 Bad Case，并同时观察质量、安全、时延和成本。

## 数据集职责

| 阶段 | 是否更新参数 | 主要用途 |
| --- | --- | --- |
| 训练集 | 是 | 拟合参数 |
| 验证集 | 否 | 选超参数、早停、比较 checkpoint |
| 测试集 | 否 | 调参结束后的最终估计 |
| 线上流量 | 否 | 观察真实请求分布和系统表现 |

验证集被反复用于决策后也会发生间接过拟合，不能再把它当成完全独立证据。训练 loss 很低只说明训练目标拟合较好，不证明回答有用、可靠或安全。

## 正确的评测状态

三个开关互相独立：

1. `model.eval()`：改变 Dropout、BatchNorm 等模块行为；
2. `torch.no_grad()` / `torch.inference_mode()`：禁止构建反向图；
3. 不调用 `optimizer.step()`：确保参数不更新。

```python
@torch.no_grad()
def evaluate(model, loader, loss_fn, device):
    was_training = model.training
    model.eval()
    loss_sum, count = 0.0, 0
    for x, y in loader:
        logits = model(x.to(device))
        losses = loss_fn(logits, y.to(device))  # reduction="none"
        loss_sum += losses.sum().item()
        count += losses.numel()
    model.train(was_training)
    return loss_sum / count
```

大小不同的 batch 不能直接平均各 batch mean，应累计总损失并除以有效样本/token 数。`eval()` 不会自动关闭梯度，`no_grad()` 也不会自动关闭 Dropout。

## 指标分层

- **训练目标指标**：token loss、perplexity；反映概率建模，不等同于指令遵循。
- **任务指标**：accuracy、F1、exact match、pass@k、检索相关指标等。
- **生成质量**：正确性、完整性、引用依据、格式和风格，可结合规则、人评和 Judge。
- **系统指标**：成功率、TTFT、TPOT、吞吐、token 用量、错误率和成本。
- **安全指标**：攻击成功率、隐私泄露、越权工具调用、拒答不足与过度拒答。

总分会掩盖能力差异。结果应按任务、难度、语言、输入长度、模型版本和风险类别分层，并保留置信区间、样本数与样本级输出。

## LLM-as-a-Judge

Judge 适合评估开放式输出，但评分本身也是一个模型预测。常见偏差包括位置偏差、长度偏好、自我偏好、措辞敏感和对评分说明理解不一致。

降低风险的方法：固定 rubric；随机交换候选顺序；要求先抽取证据再打分；用人工标注集校准；记录 Judge 模型、提示和采样参数；对高风险结论做人审。Judge 分数是测量结果，不是绝对真值。

## Bad Case 闭环

一个可复现 Bad Case 至少包含：

```text
样本与系统版本
→ 期望行为和判分依据
→ 实际输出及中间证据
→ 错误分类
→ 可复现条件
→ 根因假设
→ 修复方式
→ 固定为回归样例
```

根因可能来自数据、模型、Prompt、检索、工具、解码或评测器。应先聚类稳定失败模式，再决定增加训练数据、修改系统还是调整评测，避免为单一样本盲目补数据。

## 安全评测

安全不能只测“是否拒答”，至少覆盖：

- 有害内容与违法协助；
- 隐私、训练数据记忆与敏感信息泄露；
- Prompt injection、越权和工具滥用；
- 事实性误导及高风险领域错误；
- 过度拒答对正常任务的可用性损伤。

红队样本用于发现未知失败，固定安全回归集用于阻止已知问题复发。平均安全分之外还要看最坏案例、攻击成功率和不同风险类别的尾部表现。

## 可观测性与发布门槛

线上记录应支持重现一次请求，同时遵循隐私和最小化原则：模型/adapter、Prompt、Tokenizer、知识库和工具版本；输入输出的脱敏摘要；采样参数；检索与工具轨迹；token 数、延迟、错误和用户反馈。

发布门槛应预先定义：核心质量不得低于基线、安全关键用例必须通过、成本和延迟不得超阈值，并准备可执行回滚。上线后监控数据漂移、失败类型分布和指标尾部，而不只看平均值。

## 易错点

> [!warning] 指标提升可能是评测污染
> 训练数据包含测试题、Prompt 针对固定 benchmark 优化、Judge 或答案模板泄漏，都可能制造虚假提升。发布判断必须同时核对数据独立性、样本级差异、能力回退和统计不确定性。

## 掌握要求

- [ ] 能区分训练、验证、测试和线上数据的职责。
- [ ] 能正确组合 `eval()`、梯度模式和指标加权。
- [ ] 能为一项能力定义数据、配置、指标、基线和发布门槛。
- [ ] 能识别并控制 LLM-as-a-Judge 的主要偏差。
- [ ] 能把 Bad Case 转成可复现回归样例和修复决策。
- [ ] 能列出安全与线上可观测性的最小证据集。
