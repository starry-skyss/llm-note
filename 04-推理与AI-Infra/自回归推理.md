# 自回归推理

> [!abstract] 核心结论
> Decoder-only 模型先并行处理整个 prompt（Prefill），再串行地一次生成一个 token（Decode）。两阶段的并行度和瓶颈不同：Prefill 通常计算密度更高，Decode 需要反复读取模型权重与历史缓存，持续生成速度受内存带宽、batch 和调度显著影响。

## 生成循环

语言模型在第 $t$ 步估计：

$$
p(x_t\mid x_{<t})
$$

基础循环为：

```text
已有 token
→ 模型前向
→ 取最后位置 logits
→ 温度缩放与候选过滤
→ 贪心或采样得到新 token
→ 追加到序列
→ 直到 EOS、长度上限或停止条件
```

同一序列的第 $t+1$ 个 token 依赖第 $t$ 个 token，因此 Decode 在时间维天然串行；多个请求和一个 batch 内的矩阵计算仍可并行。

## Prefill 与 Decode

| 阶段 | 每个请求的新输入 | 缓存行为 | 常见瓶颈 |
| --- | --- | --- | --- |
| Prefill | 整个 prompt，通常多个 token | 计算并建立各层历史 K/V | 并行度高，长 prompt 常偏计算密集 |
| Decode | 每轮一个新 token | 读取历史 K/V，追加本步 K/V | 串行迭代，常受带宽与调度影响 |

Prefill 中 prompt token 的隐藏状态可利用因果 mask 一次并行计算。Decode 则只有一个新 Query，但要访问不断增长的历史 [[KV Cache]]。因此两阶段不应只用一个“平均每 token 延迟”描述。

## 采样与停止

对 logits $z$ 使用温度 $\tau$：

$$
p_i=\operatorname{softmax}(z_i/\tau)
$$

较低温度让分布更尖锐，较高温度增加随机性。Top-k 保留分数最高的 $k$ 个候选，Top-p 保留累计概率达到阈值的最小集合，再重新归一化采样。它们改变解码分布，不改变模型参数或补充模型知识。

生产生成还需处理：每个请求独立 EOS、最大新 token 数、stop sequence、重复惩罚、随机种子和被提前结束序列的 batch 移除。

## 复杂度直觉

长度为 $T$ 的全序列 Attention 需要构造 $T\times T$ 的位置关系，计算量约为 $O(T^2D)$。若每生成一步都重新运行完整增长序列，会重复计算历史隐藏状态。

使用 KV Cache 后，新 token 只新增一行 Attention 分数；单步对历史长度仍近似线性，累计生成长度增长后仍不是常数成本。实际时间还包含 Q/K/V 投影、FFN、权重加载、kernel 启动、batch 调度和通信，不能只用大 O 推断端到端性能。

## 服务指标

| 指标 | 含义 | 主要受影响阶段 |
| --- | --- | --- |
| TTFT | 请求到首 token 的时间 | 排队 + Prefill + 首次 Decode |
| TPOT / ITL | 输出 token 间的平均时间/间隔 | Decode |
| E2E latency | 请求到完整响应结束 | 两阶段与输出长度 |
| Throughput | 单位时间完成的 token 或请求 | batch、调度和资源利用率 |
| Concurrency | 同时活跃请求数 | KV 内存、SLA 与调度 |

提高吞吐可能通过增大 batch 延长单请求等待；压低 TTFT 也可能牺牲总体利用率。压测必须报告输入/输出长度分布、并发模型、硬件、精度和采样设置。

## 训练与推理的区别

- 训练一次并行处理整段序列，需要保存反向传播激活并对多个位置计算 loss。
- 推理不反传，但 Decode 串行并长期保留历史 K/V。
- 常规全序列训练通常不使用推理式 KV Cache；参数不断更新，缓存历史状态也不适用于训练目标。
- `model.eval()` 与 `no_grad()` 不会自动启用 Cache，模型接口和推理引擎必须显式支持。

## 易错点

> [!warning] 教学生成循环通常没有实现高效推理
> 把完整 `idx` 每轮重新传入模型并截断到上下文窗口，只演示自回归语义，不代表已使用 KV Cache。判断是否缓存，应检查模型是否接收并返回每层 `past_key_values`，以及位置 ID 和 mask 是否随缓存偏移正确更新。
