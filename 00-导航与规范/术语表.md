# 大模型术语表

> [!abstract] 定位
> 本页用于快速检索，不替代概念笔记。每项只保留一句定义和唯一主归属；需要机制、公式或实现时进入对应概念页或领域导航。

## 基础与模型

主归属：[[基础与模型]]

- **LLM（Large Language Model）**：以大规模数据训练、对 token 序列建模并生成内容的语言模型。
- **[[深度学习训练基础]]**：围绕前向、损失、反向传播和参数更新组织的神经网络训练主线。
- **Embedding**：把离散 ID 或其他对象映射为连续向量的可学习或预训练表示。
- **[[Transformer]]**：以 Attention、前馈网络、残差和归一化为核心模块的序列模型架构。
- **[[Attention]]**：由 Query 与 Key 决定权重，再对 Value 加权聚合信息的机制。
- **[[MHA、MQA与GQA]]**：通过不同的 K/V head 共享程度权衡注意力表达与推理成本的三类结构。
- **[[位置编码]]**：向缺少顺序感知的 Attention 注入绝对或相对位置信息的方法。
- **Chain of Thought（CoT）**：让模型显式生成中间推理步骤的提示或训练方式，不等同于模型内部机制。
- **GLM**：可指特定的自回归空白填充预训练框架或相关模型系列，不能与广义线性模型混淆。

## 数据与训练

主归属：[[数据与训练]]

- **Token**：[[Tokenizer]] 定义的离散文本单位，可能是字符、字节、词或子词片段。
- **[[Tokenizer]]**：负责文本切分、token 与 ID 映射以及特殊标记处理的组件。
- **Vocabulary**：Tokenizer 和模型能够表示的 token 集合。
- **[[预训练与样本构造|Pre-training]]**：通过自监督样本和语言建模目标学习通用能力的初始训练阶段。
- **Fine-Tuning**：在已有模型基础上用新数据和目标继续更新参数的训练过程。
- **Knowledge Distillation**：让学生模型学习教师模型输出或行为，以压缩或迁移能力的方法。

## 后训练与评测

主归属：[[后训练与评测]]

- **[[后训练与对齐|SFT]]**：使用输入与目标回答样例进行监督微调，使模型学习指令和任务行为。
- **Instruction Tuning**：用多任务自然语言指令数据进行的微调，通常采用 SFT 目标。
- **[[参数高效微调|LoRA]]**：冻结基座参数并训练低秩权重增量的参数高效微调方法。
- **[[参数高效微调|QLoRA]]**：在量化基座模型上训练 LoRA 适配器，以进一步降低微调显存。
- **Preference Data**：记录同一输入下回答相对优劣的数据，常见形式为 chosen/rejected。
- **Reward Model**：根据偏好数据学习为回答提供相对奖励分数的模型。
- **[[后训练与对齐|RLHF]]**：利用人类反馈形成的奖励信号，通过强化学习优化语言模型的方法族。
- **[[后训练与对齐|DPO]]**：直接使用偏好对优化策略，而不运行完整在线强化学习环路的方法。
- **GRPO**：利用同一问题的一组候选结果构造相对优势并优化策略的方法。
- **Alignment**：使模型行为更符合目标意图、偏好和安全要求的训练与系统过程。
- **[[大模型评测|Evaluation / Eval]]**：用明确任务、数据、配置和指标测量模型或系统表现的过程。
- **Benchmark**：用于可重复比较能力的一组任务、数据、指标和评测规则。
- **LLM-as-a-Judge**：让语言模型按评分标准评价其他模型输出的评测方式。
- **Bad Case**：未达到预期的具体失败样例及其可复现证据。
- **Hallucination**：模型生成流畅但缺少依据、与材料冲突或无法可靠验证的内容。

## 推理与 AI Infra

主归属：[[推理与AI-Infra]]

- **[[自回归推理|Inference]]**：使用固定模型参数逐 token 生成结果的运行阶段。
- **Temperature**：缩放 logits、调节采样分布尖锐程度的解码参数。
- **Top-k**：只在概率最高的 k 个候选中重新归一化并采样。
- **Top-p**：在累计概率达到阈值的最小候选集合中重新归一化并采样。
- **[[KV Cache]]**：缓存历史 token 在各层的 Key/Value，避免自回归生成时重复计算。
- **[[PagedAttention]]**：以逻辑块到物理块的映射管理动态 KV Cache 的 serving 技术。
- **Quantization**：用较低数值精度表示权重、激活或缓存，以降低资源消耗。

## RAG 与 Agent

主归属：[[RAG与Agent]]

- **RAG**：生成前检索外部资料并放入上下文，以提供可更新知识和证据的系统方法。
- **Vector Database**：面向向量存储、元数据过滤和近似相似度检索的数据系统。
- **Reranker**：对第一阶段召回结果进行更精细相关性评分和重排的模型或算法。
- **Agent**：围绕目标持续获取上下文、选择动作、调用工具并观察结果的系统。
- **Tool**：供模型或 Agent 读取信息、计算或改变外部状态的可调用能力。
- **Tool Calling**：选择工具、生成参数、执行、接收结果并继续处理的完整过程。
- **Function Calling**：让模型按照预定义名称和参数 Schema 输出结构化调用请求的机制。
- **Agent Skill**：为一类重复任务封装触发条件、步骤、规则和资源的可复用方法。
- **Agent Memory**：保存、压缩、检索并重新注入历史信息的机制。
- **MCP**：用于 AI 应用发现和连接外部工具、资源与提示的开放协议。
- **Multi-Agent**：多个 Agent 通过分工、通信或并行协作完成任务的系统形式。

## 应用与前沿

主归属：[[应用与前沿]]

- **Context**：模型当前推理实际可见的系统指令、消息、资料和工具结果集合。
- **Context Window**：模型单次能够处理的 token 容量边界。
- **Prompt**：向模型描述任务、背景、约束、数据和输出要求的输入内容。
- **User Prompt**：最终用户在当前任务中提交的请求和材料。
- **System Prompt**：应用提供的高优先级行为规则和边界，不替代真实权限控制。
- **Harness**：围绕模型或组件准备输入、连接能力、驱动执行和收集结果的支撑层。
- **Agent Harness**：为 Agent 提供工具、状态、执行循环、权限和错误处理的运行支撑层。
- **Framework**：为一类应用提供组件、生命周期、扩展点和控制流程的软件基础。
- **Pipeline**：按相对固定阶段传递和处理数据或任务的技术流程。
- **Workflow**：包含角色、条件、审批、回退和系统动作的完整任务流程。
- **Claude Code**：Anthropic 的智能体编程产品，由模型、工具和执行环境共同组成。
- **Codex**：OpenAI 的软件工程智能体产品名称，也有历史模型含义，需结合语境区分。
