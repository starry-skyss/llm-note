# 大模型笔记规范

> [!abstract] 核心原则
> 导航页负责地图，概念页负责唯一解释，论文页负责证据，术语表负责暂存，链接负责表达关系。成熟后再拆分，引用代替复制。

## 1. 结构职责

### 领域导航页（MOC）

每个领域只有一个 MOC，负责：

- 说明该领域解决什么问题及其边界；
- 给出推荐学习顺序和当前已有笔记；
- 维护待建设主题；
- 链接本领域的直接子笔记，并提供返回总入口的“属于”链接。

MOC 不承载大段概念正文，也不重复概念页的公式和代码。

### 概念页

一个概念只能有一个主归属页，正文围绕一个可回答的问题展开。其他文件需要该概念时，只保留必要上下文并用 WikiLink 指向主页面。

概念页推荐使用 [[_概念笔记模板]]，按需要保留以下模块：核心结论、问题、机制、公式与 Shape、对比、实现、易错点、掌握要求、关联和来源。

### 术语表

[[术语表]] 只保存一句定义和主要领域，用于：

- 尚不足以独立成页的名词；
- 拼写、缩写和同义词查询；
- 将读者导向已有概念页或领域 MOC。

术语提升为概念页后，术语表只保留一句摘要和链接。

### 论文页

论文页保存单篇论文的动机、方法、实验、证据和批判性评价；主干概念页保存跨论文仍成立的归纳结论。论文使用 [[_论文分析模板]]，并由 [[论文索引]] 管理。

## 2. 目录边界

| 目录 | 主职责 |
| --- | --- |
| `01-基础与模型` | 数学、神经网络、Transformer、模型结构 |
| `02-数据与训练` | 数据、Tokenizer、预训练、训练稳定性 |
| `03-后训练与评测` | SFT、偏好优化、Eval、安全与可观测性 |
| `04-推理与AI-Infra` | 解码、推理服务、硬件、分布式和系统优化 |
| `05-RAG与Agent` | 检索增强、工具调用、记忆和任务执行 |
| `06-应用与前沿` | 应用工程、多模态和尚未稳定的新方向 |
| `论文` | 论文索引、模板和单篇分析 |
| `99-归档` | 已被替代但仍需回查的旧内容 |

边界冲突时，以“这条内容主要回答什么问题”为准。例如，KV Cache 的算法机制归推理；它的跨 GPU 内存管理归 AI Infra；它对 Transformer 的接口只在模型页简述。

## 3. 属性规范

所有非归档 Markdown 文件使用：

```yaml
---
type: moc | concept | glossary | paper | guide
domain: 基础与模型 | 数据与训练 | 后训练与评测 | 推理与AI-Infra | RAG与Agent | 应用与前沿 | 跨领域
status: seed | active | stable | archived
aliases: []
---
```

- `type`：文件承担的职责。
- `domain`：唯一主归属；跨领域入口、模板和规则使用 `跨领域`。
- `status`：成熟度，不代表内容正确性的绝对保证。
- `aliases`：只填写真实常用别名、英文名或缩写，不堆关键词。

不要在 YAML 中复制正文的关联网络。正文只记录真实存在的层级、依赖或专题关系，不为了让图谱显得完整而添加链接。

## 4. Markdown 与 Obsidian 格式

- 每个文件只能有一个一级标题；主体使用二级标题，内部层次使用三级标题。
- 核心结论使用 `> [!abstract]`，高风险误区使用 `> [!warning]`，实验或具体例子可使用 `> [!example]`。
- 公式使用 LaTeX；代码围栏必须标语言；表格只用于真正需要横向比较的内容。
- 文件名使用稳定、唯一的概念名，不添加日期或“最终版”等状态词。
- 关系使用 `[[页面名]]` 或 `[[页面名#章节]]`；重命名后必须检查入链和出链。
- 来源应紧邻结论或集中在“来源”小节，并说明它支持什么内容。

### 链接与层级

链接只用于表达以下关系：

1. **属于**：子笔记返回它的直接上一级。上一级可以是领域 MOC，也可以是更大的概念页。
2. **组成或依赖**：不阅读目标页就难以理解当前机制，或目标确实是当前概念的组成部分。
3. **具体证据**：某篇论文直接提出、改进或验证了当前概念。

推荐形成稀疏、可解释的树形主干：

```text
README
└─ 领域 MOC
   └─ 较大的概念页
      └─ 细分概念页
```

- MOC 不机械链接其他领域、术语表或论文索引；跨领域链接只在内容存在直接依赖时添加。
- 概念页不预设“上游、下游、相关论文”等空关系；没有真实目标时删除该行或整个“关联”小节。
- 一个概念可能有多个用途，但“属于”只选择当前知识库中最自然的直接父页。
- 学习父概念时从正文进入子概念；阅读完子概念后通过“属于”返回父页。

## 5. 何时创建独立概念页

满足以下至少三项时，才从术语表提升为独立页：

- 已有稳定定义和清晰边界；
- 能形成至少三个有内容的二级章节；
- 存在值得保留的公式、Shape、代码或实验；
- 会被两个以上页面引用；
- 后续预计持续增长；
- 能写出明确的掌握要求和易错点。

否则先留在术语表或 MOC 的“待建设主题”，不要批量制造空文件。

## 6. 内容去重规则

1. 定义、公式和完整推导只在主概念页出现一次。
2. MOC 只写导航摘要；术语表只写一句定义。
3. 工具和框架放在其解决的问题下，不因产品名称单独扩张目录。
4. 同一内容横跨领域时，其他页面写一至三句上下文后链接主归属。
5. 无法确定归属时，选择未来会承担最完整解释、被引用最多的页面。

## 7. 学习与维护流程

```text
收集材料
→ 判断主领域
→ 搜索已有定义和链接
→ 标记来源与可信度
→ 提炼核心结论
→ 补机制、边界、易错点和掌握要求
→ 只建立真实的层级、依赖或证据链接
→ 检查重复、链接与格式
→ 根据成熟度更新 status
```

`active` 变为 `stable` 前至少确认：核心问题有回答；公式和 Shape 可核验；易错点不是泛泛提醒；来源可追踪；没有与其他主页面重复。

## 8. 论文如何回填主干

- 单篇文件命名为 `YYYY-论文简称.md`。
- 论文页用“属于”链接返回 [[论文索引]]；`domain` 属性记录它的主要领域。
- 只有论文确实提出、改进、使用或验证某个概念时，论文页才链接该概念。
- 实验设置、表格、局限和个人批评留在论文页。
- 概念页只链接与正文结论直接相关的具体论文，不链接总论文索引；论文页与概念页必须双向引用。
- 只有经过核查、具有复用价值的结论才回填概念页，并保留具体论文链接。
- 多篇论文形成稳定研究线后，才增加专题综述；不按每篇论文创建新的主干分类。

## 9. 草稿迁移约定

本轮不迁移 `草稿`。未来迁移时：

1. 原始草稿保持可回查；
2. 先确定唯一主归属，再写入；
3. 合并已有内容，不追加第二份解释；
4. 对明显错误先纠正，对不确定内容标记待核验；
5. 只迁移长期有价值的结论、推导、代码和特殊案例；
6. 完成后检查来源、链接、公式和重复段落。

## 10. 变更验收

- 文件路径符合目录职责，文件名在整个库内唯一。
- YAML 的 `type/domain/status` 使用规定值。
- 一个文件只有一个一级标题，代码围栏和公式分隔符闭合。
- WikiLink 能解析，不引用已删除文件。
- 概念页有唯一主归属，MOC 和术语表没有复制其正文。
- 已建立关系的论文与概念页能够双向追踪；没有关系时不创建占位链接。
- 删除或压缩材料前，先归档仍有回查价值的原文。
