# 位置编码

> [!abstract] 核心结论
> Self-Attention 本身不会仅凭 token 在序列中的排列得知先后次序；位置编码把绝对位置或相对位置关系注入表示或注意力计算。它解决“顺序如何进入模型”的问题，但不负责限制未来信息。

## 解决的问题

若只对输入 token 做同样的 Q/K/V 投影，Attention 的计算不会天然区分“第几个位置”。语言中的顺序、距离和方向会影响含义，因此模型需要额外的位置机制。

## 方法谱系

### 绝对位置表示

最直接的方法为每个位置 $p$ 构造向量 $P_p\in\mathbb{R}^D$，与 token embedding 相加：

$$
H_p=E(x_p)+P_p
$$

`P` 可以是可学习参数，也可以由固定函数生成。原始 Transformer 使用多频率正弦/余弦：

$$
PE(p,2i)=\sin\left(p/10000^{2i/D}\right)
$$

$$
PE(p,2i+1)=\cos\left(p/10000^{2i/D}\right)
$$

固定正弦位置无需学习位置表；可学习绝对位置能由数据选择表示，但通常只为训练时预设的最大位置分配参数。两者都先表示“当前位置是谁”，相对关系需要模型后续自行利用。

### 相对位置方法

相对方法让 Attention 分数或 Value 聚合显式依赖位置差 $i-j$，更直接地表达方向和距离。实现可以是相对位置 bias、相对 Key/Value 表示或对 Q/K 的位置变换；“相对位置”是一类建模思想，不对应唯一公式。

### RoPE

RoPE（Rotary Position Embedding）把每个 Attention head 的 Q/K 最后一维两两配对，在位置 $m$ 处按不同频率旋转：

$$
R(m,\theta)=
\begin{bmatrix}
\cos(m\theta)&-\sin(m\theta)\\
\sin(m\theta)&\cos(m\theta)
\end{bmatrix}
$$

对二维子向量 $q$、$k$：

$$
q_m'=R_mq,\qquad k_n'=R_nk
$$

由于旋转矩阵满足：

$$
(R_mq)^{\mathsf T}(R_nk)=q^{\mathsf T}R_{n-m}k
$$

Q/K 点积会显式依赖相对位置差 $n-m$。RoPE 同时使用多组频率；它改变 Q/K 的数值但不改变 Shape，V 通常不旋转。

```text
X [B,T,D]
→ Q/K/V [B,H,T,d_h]
→ 对 Q/K 的二维特征对应用 RoPE
→ QK^T
→ causal mask
→ softmax
→ 加权 V
```

## 实现要点

设 `x1=x[..., ::2]`、`x2=x[..., 1::2]`，二维旋转的核心可写为：

```python
def apply_rope(x, cos, sin):
    x_even, x_odd = x[..., ::2], x[..., 1::2]
    y_even = x_even * cos - x_odd * sin
    y_odd = x_even * sin + x_odd * cos
    return torch.stack((y_even, y_odd), dim=-1).flatten(-2)
```

`cos/sin` 需要能广播到 `[B,H,T,d_h/2]`。实际模型还会区分 rotary dimension、位置 ID、缓存偏移和不同的频率缩放方案。

## 对比与边界

- 位置编码回答“token 位于哪里、彼此相隔多远”；因果掩码回答“当前位置允许读取哪里”。
- Token Embedding 表示 token 身份；位置表示补充顺序，两者承担不同信息。
- “绝对”与“相对”是建模视角，不应只根据代码中是否存在位置向量来判断。
- RoPE 编码绝对位置旋转，同时让点积呈现相对位置依赖，不能简单归为“只含绝对”或“只含相对”。
- 长上下文效果不只由位置方法决定，还受训练长度、数据、频率缩放、Attention 实现和推理策略影响。RoPE 也不意味着无限长度外推。

## 易错点

> [!warning] 不要把位置编码等同于因果性
> 即使加入位置信息，如果没有正确的因果掩码，Decoder 训练仍可能读取未来 token。反过来，只有掩码也不能让模型充分表达距离与顺序关系。
