# 评测、安全与可观测性（精炼）

> 定位：把“模型是否学会、是否泛化、是否适合发布”拆成可复现的证据。现有材料对基础 loss 评估较充分，对 LLM 安全和线上可观测性覆盖较浅，缺口会明确保留。

## 数据集职责

| 阶段 | 是否更新参数 | 主要用途 |
| --- | --- | --- |
| 训练集 | 是 | 拟合参数 |
| 验证集 | 否 | 选超参数、早停、比较 checkpoint、发现过拟合 |
| 测试集 | 否 | 调参结束后的最终估计，避免反复查看 |
| 推理/线上 | 否 | 使用已训练模型处理真实请求 |

泛化误差是真实未知分布上的期望误差，验证/测试误差只是有限样本估计。训练 loss 很低只说明对训练目标拟合良好，不能单独证明模型有用或安全。

## 训练曲线的基本诊断

- 训练与验证 loss 都高：常见于欠拟合、训练不足、优化失败或数据/实现错误。
- 训练 loss 下降且验证 loss 同步下降：通常说明学习有效。
- 训练 loss 继续下降而验证 loss 上升：典型过拟合信号。
- 二者都下降但长期差距扩大：泛化风险增加，需要结合任务指标和数据分布判断。

分类任务中，loss 衡量概率分布质量，accuracy 只看最终类别是否正确；两者不能互相替代。语言模型的 token loss/perplexity 也不等同于指令遵循、真实性或人类偏好。

## 正确的评测状态

三个开关相互独立：

1. `model.eval()`：切换 Dropout、BatchNorm 等模块的运行模式。
2. `torch.no_grad()` 或 `torch.inference_mode()`：不构建反向传播图，减少内存和计算。
3. 不调用 `optimizer.step()`：确保参数不更新。

`eval()` 不会自动禁止梯度；`no_grad()` 不会自动关闭 Dropout；两者都不会替你计算或汇总指标。

```python
@torch.no_grad()
def evaluate(model, loader, loss_fn, device):
    was_training = model.training
    model.eval()
    loss_sum, item_count = 0.0, 0
    for x, y in loader:
        x, y = x.to(device), y.to(device)
        logits = model(x)
        losses = loss_fn(logits, y)  # reduction='none'
        loss_sum += losses.sum().item()
        item_count += losses.numel()
    model.train(was_training)
    return loss_sum / item_count
```

若 batch 大小不同，不能简单平均“各 batch 的平均 loss”；应累计 loss 总和并除以有效样本/token 数。

## LLM Eval 应覆盖什么

现有草稿给出的核心维度包括：

- 指令遵循与任务完成度；
- 数学、代码等领域能力；
- 真实性与幻觉；
- 安全性和拒答行为；
- 风格与格式；
- 推理成本、延迟与稳定性。

单个总分会掩盖能力差异。更可靠的做法是按任务、难度、语言、输入长度和风险类型分层报告，同时保留样本级结果。

## Bad Case 分析

Bad case 不应只记录“回答错了”，至少应包含：

```text
样本与版本
→ 期望行为/判分标准
→ 实际输出
→ 错误类型
→ 可能原因（数据、提示、检索、模型、解码或评测器）
→ 是否可稳定复现
→ 修复措施
→ 修复后的回归测试
```

建议将 bad case 聚类，而不是为单一样本盲目补数据。形成频繁失败模式后，再决定是改数据、训练目标、提示、工具链还是推理配置。

## 安全与可观测性现状

当前草稿只把安全性列为 Eval 维度，没有形成完整方法；可观测性也缺少指标、日志和线上反馈设计。因此目前只保留学习入口：

- 安全：有害内容、越权、隐私泄露、提示注入、拒答过度与不足、红队测试。
- 可观测性：模型/提示/数据版本、输入输出与脱敏、错误率、延迟、token 用量、工具调用、用户反馈和漂移。
- 发布门槛：固定回归集、关键安全用例、质量/成本阈值、回滚条件。

这些条目不能被当前笔记视为“已经掌握”，后续需要独立补充。

## 易错点

- 验证集参与反复决策后，也可能被间接过拟合；最终测试集必须保持独立。
- 自动评测器本身可能有位置、长度、措辞和模型偏差，不能把 judge 分数当作绝对真值。
- `model.eval()` 不等于“不训练”，是否更新取决于是否反传并执行优化器。
- 评测期间恢复原训练模式比无条件 `model.train()` 更稳健。
- 只报告平均值会掩盖尾部风险；安全问题尤其需要看最坏案例和分类统计。
- 对生成模型，只比较 loss 不足以判断回答质量；只做人评又难以复现，应组合使用。
