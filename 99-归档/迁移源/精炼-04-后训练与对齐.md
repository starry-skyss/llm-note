# 后训练与对齐（精炼）

> 定位：建立预训练之后的训练地图，明确 SFT、偏好数据、Reward Model、DPO 与 RLHF 的数据和目标差异。现有草稿只覆盖概念层，因此本篇不展开算法推导。

## 总体流程

```text
预训练模型
→ SFT：学会按指令和对话格式回答
→ 偏好对齐：学习哪些回答更符合目标偏好
   ├─ DPO 等直接偏好优化
   └─ Reward Model → RL 优化（如 RLHF）
→ Eval 与 bad case 分析
→ 回流数据，再训练与再评测
```

后训练不是单一算法，而是围绕目标行为进行的数据、训练和评测闭环。基础能力主要来自大规模预训练；后训练更侧重激活、组织和约束这些能力，改变指令遵循、风格、安全性与偏好表现。

## SFT：监督微调

SFT（Supervised Fine-Tuning）通常使用高质量的“输入 → 目标回答”数据：

```text
system / user / context
→ assistant response
```

本质仍是 next-token cross entropy，只是通常仅对希望模型学习的 assistant token 计算 loss。它主要让模型学会：

- 指令和聊天模板；
- 任务所需的回答结构与风格；
- 给定输入下应输出什么内容。

SFT 是监督学习，不等同于强化学习，也不自动保证真实性、安全性或对未知分布的泛化。

## 偏好数据

典型样本：

```text
prompt
chosen    # 更符合偏好的回答
rejected  # 较差的回答
```

偏好可能来自人工标注、规则、模型评审或混合流程。`chosen` 表示相对更优，不意味着绝对正确；偏好数据质量取决于任务定义、标注标准和评审一致性。

## Reward Model、RLHF 与 DPO

| 方法 | 主要输入 | 学到/优化的对象 | 关键区别 |
| --- | --- | --- | --- |
| Reward Model | prompt 与回答偏好比较 | 给回答分配相对奖励的模型 | 它负责评分，不负责生成最终回答 |
| RLHF | 奖励信号与生成样本 | 通过强化学习更新策略模型 | 训练链路更长，需控制策略偏移等问题 |
| DPO | `prompt/chosen/rejected` | 直接提高 chosen 相对 rejected 的偏好 | 通常不显式训练 Reward Model，也不运行完整在线 RL 环路 |

二者目标相近但路径不同：DPO 属于偏好优化方法，通常不应直接称为标准强化学习流程；RLHF 则显式使用奖励并通过强化学习更新语言模型。

## Loss 与 Reward

- Loss 是优化器直接最小化的可微目标，如 token 交叉熵。
- Reward 是希望最大化的行为评价，可能延迟、稀疏、不可微或只在完整回答后获得。
- 数学上可写成 `loss = -reward`，但这不代表工程中的监督学习和强化学习过程相同。
- Reward Model 的分数是偏好代理，不等同于真实世界目标；模型可能利用评分漏洞，因此必须结合独立 Eval 和 bad case。

## 参数高效微调

- LoRA 冻结大部分基础模型参数，只训练注入到部分线性层的低秩增量，以减少可训练参数和优化器状态。
- QLoRA 在量化的基础模型上训练 LoRA 适配器，进一步降低显存需求。
- “参数高效”主要描述训练资源和参数更新方式，不代表数据、目标或评测要求可以降低。

## 后训练闭环

```text
定义目标与评价标准
→ 建立 baseline eval
→ 分析 bad cases
→ 构造 SFT / preference 数据
→ 训练
→ 在固定评测集和新样本上复测
→ 检查能力、安全、风格和成本回归
```

数据应由明确失败模式驱动。只看训练 loss 或偏好 loss，无法判断回答质量是否真的改善，也无法发现能力回退和 reward hacking。

## 易错点

- 预训练、SFT、偏好优化是不同阶段，但底层都可能继续更新同一个 Transformer 的参数。
- SFT 数据给目标答案；偏好数据比较答案相对好坏；Reward Model 输出评分；生成模型输出文本。
- “更符合偏好”不等于“事实正确”，偏好优化也可能放大标注偏差。
- DPO 不需要完整 PPO/RL 环路，但不能据此理解为“没有目标函数或参考约束”。
- Eval 不是一种训练方式，而是贯穿数据构建、模型选择和发布决策的独立环节。
