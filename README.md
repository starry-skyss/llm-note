# 大模型知识库

> [!abstract] 使用方式
> 本库采用“领域导航页（MOC）+ 成熟概念页 + 简明术语表”的结构。先从领域导航建立知识地图，再进入独立概念页；尚未形成体系的名词先留在术语表，不急于拆文件。

## 快速入口

| 领域 | 主要问题 | 导航 |
| --- | --- | --- |
| 基础与模型 | 模型内部怎样表示和计算 | [[基础与模型]] |
| 数据与训练 | 模型怎样从数据获得能力 | [[数据与训练]] |
| 后训练与评测 | 怎样调整行为并判断效果 | [[后训练与评测]] |
| 推理与 AI Infra | 模型怎样高效训练、运行和服务 | [[推理与AI-Infra]] |
| RAG 与 Agent | 怎样接入知识、工具与任务循环 | [[RAG与Agent]] |
| 应用与前沿 | 怎样构建应用并跟踪扩展方向 | [[应用与前沿]] |

其他入口：

- [[术语表]]：快速查概念；只保留一句定义和主归属。
- [[论文索引]]：管理单篇论文、阅读状态和对主干知识的影响。
- [[笔记规范]]：新增、拆分、链接和整理笔记时的唯一规则来源。
- [[_概念笔记模板]]、[[_论文分析模板]]：新建笔记的统一模板。

## 推荐学习顺序

```text
基础数学与神经网络
→ Transformer / Attention / 位置编码
→ Tokenizer、数据与预训练
→ SFT、偏好优化与 Eval
→ 推理优化与 AI Infra
→ RAG、Agent 与应用工程
```

这只是主依赖链，不是强制的线性课程。评测、安全、可观测性和工程实践会横跨多个阶段。

## 笔记状态

| `status` | 含义 |
| --- | --- |
| `seed` | 只有问题、提纲或少量结论，等待建设 |
| `active` | 正在学习和补充，结构可能变化 |
| `stable` | 已形成稳定解释，可作为其他笔记的主引用 |
| `archived` | 已被替代，仅用于回查 |

## 新内容如何进入知识库

```text
得到一条新知识
→ 判断属于哪个领域
→ 查术语表和现有概念页
→ 已有主归属：补充原页并建立链接
→ 只有零散定义：加入术语表
→ 已形成稳定机制、对比或实现：提升为独立概念页
→ 来自单篇论文：先写论文笔记，再提炼稳定结论
```

## 链接原则

- 入口页只链接下一级导航，领域导航只链接本领域的直接子笔记。
- 子笔记用“属于”链接返回上一级；例如：位置编码 → Transformer → 基础与模型 → 本页。
- 正文只在理解当前内容确实需要另一个概念时建立链接。
- 论文索引不与所有概念互链；只有某篇论文实际涉及某个概念时，才在两页中互相引用。

> [!warning] 不要这样整理
> 不按学习日期、课程名称或聊天轮次创建主干笔记；不在多个文件复制同一段定义或公式；不因一个热点名词立即创建空白概念页。
